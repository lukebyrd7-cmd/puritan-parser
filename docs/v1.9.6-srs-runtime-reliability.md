# v1.9.6 — SRS integrity and runtime reliability

## Scope and starting point

This release started from clean `main` at `55c444a3b19b9fb5a3cc1558fa8697d97c9b44f0`, after fetching and confirming that local `main`, `origin/main`, and `FETCH_HEAD` matched. It does not add accounts, synchronization, or cloud backup.

## Observed contradiction and root cause

The reported state—Known, C — Developing, no scheduled review, `successCount: 3`, zero review events—was reproducible from a manual Known transition. `markEntryKnown` forced `successCount` to at least three so the older scheduler-derived status rule would regard the word as Known. It added a `marked-known` history event, which is deliberately not a recall event. The Word Page then labeled `successCount` as “Successful Reviews,” while its total and history summary counted only `recognized` and `missed` history events. The three labels therefore described two different populations.

The same coupling broke Return to Learning: `introduceEntry` changed the persisted status to Learning but retained the fabricated three-success streak and `9999-12-31` due sentinel. The derived status selector could immediately promote it back to Known.

The correction is semantic and nondestructive:

- `successCount` is a scheduler success streak, never a historical review count.
- Recognized and total review counts are derived from the authoritative per-word review events.
- A manual Known transition no longer fabricates a streak or active interval.
- Return to Learning resets the active scheduling streak, interval, and due date while preserving genuine history.
- Existing legacy manual records are not rewritten. Compatibility selectors show zero reviews when they have no review events, even if an old record contains `successCount: 3`.

## Authoritative learning model

| Concept | Authoritative field or selector | Semantics |
| --- | --- | --- |
| Vocabulary identity | `VocabularyLearning.lemmaId(entry)` / persisted record `id` | Stable `lemma:<language>:<identity>` key; unchanged. |
| Persisted status | record `status` plus `knownSource` | Manual and self-reported Known states remain explicit. Review progression is validated by `learningStatusForRecord`. |
| Public status | `learningStatusForRecord` / `learningStatusDetails` | New, Learning, Reviewing, Known, or Known by Self-Report. Word Page maps these to its simpler public labels. |
| Known source | record `knownSource` | `manual`, `self_reported`, or `review`; Word Page renders calm public labels. |
| Scheduler streak | record `successCount` | Consecutive scheduling evidence used for transitions and interval choice. It is not “successful reviews.” |
| Interval and due date | record `intervalDays` and `due` | Active only when `due` is a real date. `9999-12-31` means not scheduled; the selector reports both next review and interval as Not scheduled. |
| Review history | record `history`, selected through `reviewEvents` | The authoritative recall-event stream. `recognized`/`missed` events and confidence events normalize to the same population. Introduction and manual-status events are not reviews. |
| Review totals | `reviewStatistics(record)` | `total`, `recognized`, `missed`, and Again/Hard/Good/Easy counts all come from the same normalized events. Recognized can never exceed total. |
| Last review / rating | latest normalized review event, with persisted `lastReviewed` compatibility | Manual status changes do not become last reviews. |
| Mastery | `VocabularyMastery.masteryGrade(record, date)` | Uses the centralized normalized review events and current active interval; it does not infer evidence from Known status or scheduler streak. |
| Maintenance preference | `pp_maintenance_srs_preference` through `LearningPractice.loadMaintenancePreference` | Controls whether maintenance confidence changes the schedule. |
| Daily Practice totals | per-word review events through `dailyPracticeSummary` | Deduplicated by vocabulary ID and local date; recap does not count. |
| Active/resumable session | `pp_learning_sessions` | Current cards, position, submitted event IDs, difficult IDs, direction, phase, and session configuration. |
| Needs attention | `pp_learning_attention` | Independent flag; it affects candidate priority, not status, history, or mastery directly. |
| Legacy global attempts | `pp_learning_attempts` | Preserved for import/export compatibility but no longer receives a duplicate copy of new authoritative events. |
| Legacy form-card counters | old item `vocab`/`parsing` fields | Retained for legacy features; not authoritative for the shared lemma-learning model. |
| Cached statistics | progress and Learn revision caches | Derived only; invalidated by the shared learning revision and never persisted as a second learning model. |

Imports are normalized through the existing schema-version-2 vocabulary store and learning-practice import paths. No vocabulary IDs, keys, or persisted schema versions changed.

## Mastery semantics

Mastery grades use normalized recall events:

- evidence weights: Again 0, Hard 0.45, Good 0.8, Easy 1.0; legacy recognized/missed events score 1/0;
- F: the last three events are misses, or at least four attempts with accuracy below 0.35;
- D: at least two misses in the last five, or at least four attempts with accuracy below 0.60;
- A: at least eight attempts, accuracy at least 0.90, active interval at least seven days, and no recent miss;
- B: at least five attempts, accuracy at least 0.68, and no more than one recent miss;
- C: all other states, including new, sparse, imported, and manually Known records without sufficient evidence.

Known therefore does not imply A. A manually Known word with no review evidence correctly remains C — Developing. Needs attention affects practice priority, not the formula. Return to Learning preserves the historical evidence used by mastery but resets the active schedule. An Again event lowers evidence and resets the scheduler streak. Maintenance evidence participates in mastery whether or not maintenance scheduling is enabled.

## Scheduler and Known semantics

Again resets the scheduler streak, moves the word to Learning, sets a one-day interval, and records one missed event. Hard preserves at least a one-success streak and grows the current interval conservatively. Good increments the streak and uses the normal interval. Easy increments the streak and uses a larger interval. Each accepted confidence action has one stable event ID; stale or duplicate card submissions are rejected.

Manual Known writes a non-review `marked-known` event, sets no active interval, and uses the existing not-scheduled sentinel. It never invents recall. Known with Maintenance SRS off can remain unscheduled, while maintenance answers still add mastery evidence without changing status, streak, interval, or due date. Maintenance SRS on applies the normal scheduler transition. Turning maintenance off does not erase a genuine schedule already earned through Learning/Reviewing.

The UI transaction snapshots the vocabulary store, active session, and shared revision before persisting a rating. If either required write fails, it restores the snapshots, keeps the card recoverable, displays a concise retry message, and always releases the submission guard.

## Word Page simplification

The individual Word Page no longer renders its Reference heading, Grammar Handbook/Paradigm Charts/Morphology Guide links, or Reader usage-example subsection. The top-level Reference and Reader features are unchanged. Learning now shows Recognized Reviews and All Reviews from one selector, a coherent history summary, and an explicit explanation when manual Known is unscheduled because maintenance SRS is off.

## Sustained-session root cause and correction

The shared practice path did four kinds of growing work:

1. `currentCard` repeatedly normalized and cloned the complete growing session, including from inside an already-normalized transition.
2. Every render linearly searched all 5,478 Greek or 9,152 Hebrew entries for the current stable ID.
3. Every active-card render computed the whole-day summary by scanning every learning record and its history, even though the summary is only displayed on completion.
4. Every rating duplicated its event into `pp_learning_attempts`, reserialized that ever-growing global event list, and performed a second shared-revision write.

The fix uses direct bounded current-card traversal for normalized sessions, a per-language stable-ID entry map, completion-only daily-summary calculation, per-record history as the sole new-event stream, and one shared revision bump for the vocabulary/session checkpoint. The legacy global attempt store remains readable and exportable. Canonical-form preparation remains single-flight and cached; the rating path performs only a cached per-entry resolution and never rebuilds the 14,630-entry bilingual map.

Old DOM is replaced rather than retained. Equivalent card listeners are attached only to the new bounded card controls; the root keyboard handler is replaced, not accumulated. The only auto-advance timer belongs to the legacy flashcard view and is cancelled before replacement/end. Shared preparation jobs remain single-flight.
